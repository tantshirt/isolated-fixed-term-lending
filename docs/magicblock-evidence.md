## Phase 2: complete private loan

| Story | Status | Date | Evidence |
| --- | --- | --- | --- |
| 10.1 Fund, accept, repay, cancel, expire, withdraw | PASS | 2026-10-05 | `isolated_loan/scripts/private/loan.ts`, with a lender, a borrower, and an outsider, all with private USDC and wSOL balances. **Loan A:** an edit moves terms to revision 2; funding revision 1 is rejected (`StaleRevision`); funding and acceptance bind revision 2; acceptance runs the canonical Pyth check inside the TEE; repayment pays the exact debt; a second repay is rejected; a claim after repayment does nothing. **Loan B:** fund then cancel; acceptance after cancel is rejected. **Loan C:** a 60-second term; repayment after the deadline is rejected; an outsider claims the collateral for the lender, and a second claim does nothing. Final private balances match exactly. `LoanTerms` never exists on Solana. |

Findings from building it:

- **Explicit eATA permissions block programs.** If a token account carries an explicit owner-only permission, the TEE gateway returns `403 Access denied` for any transaction that passes it to a program other than SPL Token or eSPL, even when the owner signs. Without an explicit permission, the owner still reads the real balance and outsiders read a masked 0. Private balances therefore use no explicit permission. 9.3's evidence used one; the flow has changed since.
- **Base token accounts must exist.** The ER mirrors the base associated token account onto the eATA. Without one, the account does not exist inside the rollup, so `create_loan` creates the custody ATAs.
- **Large ER-only records overflow the stack.** A 2.9 KB struct overflows the 4 KB SBF stack frame, so the room thread is written in place.
- **The price source needs care.** The sponsored shard-0 Devnet feed was 97 s old at one point, so acceptance correctly failed `StalePrice`. Hermes now requires an API key (401 without one). Scripts wait for the next sponsored refresh, or post an update when `PYTH_HERMES_API_KEY` is set.
- **No automated LiteSVM run for `private_loan`.** The ER instructions need the ER runtime (magic program, permissions, eATA mirroring), so the public LiteSVM vectors are not run against `private_loan`. They are covered by the shared `loan-core` vectors and this Devnet run.
